# 围绕每天真正会用到的动作组织，不把功能堆成一张清单。

  • +打包与发布分开核心

    打包只负责把项目变成文件并写下清单，各平台再从清单取文件上传；打包一次发多个平台，某个平台失败重试时不用重新打包。

  • +卡片跟着版本号变核心

    选「补丁 / 次版本 / 主版本」后，打包卡的版本、发布说明标题与 tag、产物文件名（{version}）一起按新版本预览；手改过的说明不会被覆盖。

  • +时间线按平台分组核心

    步骤按平台分组，某个平台失败只影响它自己那组，其他平台照跑；排除故障后点「重试没成功的」接着做，不用从头再来。

  • +失败按平台回滚

    打了哪个 tag、推了哪条分支、建了哪个 Release 都有记录：能自动撤的给按钮，撤不回来的（比如 npm publish）只把命令写清楚，不替你按。

  • +打包完先挑产物

    勾了排队平台时，打包跑完会停下来让你挑这次要上传的文件，默认全选当前版本；一个都不勾就只发源码。

  • +语言规则在界面里改

    识别规则、版本号来源、打包命令、产物 glob 都能直接改，也能新建一种语言；改完立刻生效，内置档案可以一键恢复默认。

  • +凭据不用粘进页面

    GitHub 依次找 GITHUB_TOKEN、GH_TOKEN、gh auth token、git credential；npm 用 npm whoami 判断有没有登录，顶部胶囊直接显示就绪状态。

# 运行环境、技术构成和数据放在哪里，都写在这里。

运行环境

  • Node.js 20 及以上（零第三方依赖，不需要 npm install）
  • 需要本机 git；发 npm 要先在终端 npm login，发 GitHub Release 需要有可用的 token
  • GitHub token 依次从 GITHUB_TOKEN、GH_TOKEN、gh auth token、git credential 里找

你的数据

发布记录、运行日志和语言档案都在仓库的 .data/ 目录里：不写进被发布的仓库，也不经过任何服务器。凭据只从本机环境变量和 git 配置里读，不落盘。
